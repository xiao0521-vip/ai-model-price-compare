一、项目背景：这是个什么网站

这是一个对比 76 款主流 AI 大模型价格 的公开网站，地址： https://xuxiao-ai-model.pages.dev。用户可以在上面查到每款模型「每百万 token（约 75 万字）收多少钱」，并按综合成本排序、按厂商/能力筛选，还能对比 24 组云平台套餐和 Agent 桌面订阅哪个更划算。

整个网站本质上只有 两个文件：

文件内容类比
index.html页面外观 + 全部交互逻辑（筛选、排序、切换视图）商店的货架和装修
data.js全部价格数据（76 款模型 + 24 组套餐）货架上的商品

演进要解决的核心问题：早期版本里，价格是人工整理好写死在 data.js 里的。AI 模型价格变动频繁（今天降价、明天搞促销），人工维护既慢又容易错。于是项目经历了一次完整的演进——从「人工更新」变成「每天下午 4 点机器人自动抓最新价格、自动更新、自动上线」，全程不需要任何人在电脑前。

二、实现流程：数据从哪来、怎么自动更新

2.1 先回答最关键的问题：自动抓取时，访问的是 GitHub 上的文件还是本地文件？

答：访问的是 GitHub 仓库里的文件，和本地电脑没有任何关系。
每天运行任务时，GitHub 会把仓库完整复制一份到它的临时服务器上（这叫「检出」），所有抓取、修改、提交都发生在那台临时服务器里。任务跑完，临时环境即销毁。本地电脑不需要开机，本地文件不参与自动更新。本地目录只是开发者平时改代码用的「工作副本」。

2.2 数据从哪来

价格数据的来源是 OpenRouter 的公开接口（可以理解为一家「AI 模型超市」的公开价目表，任何人在浏览器打开 https://openrouter.ai/api/v1/models 都能看到）。它一次返回 446 个模型的实时价格，免密钥、免费。脚本从中挑出与我们表格匹配的模型，把「美元/token」换算成「元/每百万 token」后使用。

2.3 完整数据流转链路

一次自动更新，数据要走完下面这条链路（注意：数据永远只经过 GitHub，不经过本地电脑）：

① GitHub 临时服务器定时任务触发，把仓库最新代码完整复制一份过来
→运行脚本
② OpenRouter 公开接口脚本发请求，拿回 446 个模型的实时价格
↓ 价格经过三道质检
③ 三道防线过滤单位闸门（防算错倍数）→ 严格匹配（防止张冠李戴）→ 数据体检（防异常波动入库）
→通过质检
④ 修改 data.js只改有变动的价格数字，注释和排版原样保留
↓ 有变更才提交，无变更就此结束
⑤ 提交回 GitHub 仓库机器人（price-bot）把改好的 data.js 推回 main 分支，形成一条新提交记录
→监听到更新
⑥ Cloudflare Pages 自动部署从仓库取最新文件，1~2 分钟内发布到公网
↓
⑦ 全世界访问者打开 xuxiao-ai-model.pages.dev，看到的就是最新价格
一个容易误解的点：机器人改的不是「线上网站」，而是「仓库里的 data.js」。线上网站是 Cloudflare 从仓库抄送过去的副本——仓库一变，副本跟着重做。所以链路的终点永远是「GitHub 仓库」，它是唯一的数据源头。

三、部署方式：绑定 Cloudflare Pages 公开访问

3.1 为什么选 Cloudflare Pages

纯静态网站（只有 HTML/JS，没有后端程序）托管在 Cloudflare Pages 上：免费、全球访问快、自带 HTTPS 证书、不需要自己买服务器。它最大的特点是支持「Git 集成」——监控 GitHub 仓库，仓库一有新提交就自动重新发布。

3.2 绑定配置（一次性操作）

在 Cloudflare 控制台新建 Pages 项目并授权 GitHub 后，只填了这几项：

配置项填的值含义
仓库xiao0521-vip/ai-model-price-compare监听哪个仓库
Production branchmain只看 main 分支的变化
Build command留空纯静态站，无需编译
Build output directorydeploy/只发布这个文件夹里的内容（不含脚本和密钥相关文件）
为什么有 deploy/ 目录：仓库根目录里混着抓价脚本、测试文件、工作流配置，这些不该出现在公网上。所以网站文件单独放一份在 deploy/ 文件夹里作为「发布目录」，Cloudflare 只看这个文件夹。代价是：每次改完根目录的 index.html / data.js，必须复制一份到 deploy/（已写进运维手册）。

3.3 域名

上线地址 xuxiao-ai-model.pages.dev 由 Cloudflare 免费分配（前缀 = 项目名，创建时定死，全平台唯一）。任何人无需登录即可访问；以后也可以绑定自有域名。

四、当前运行机制：自动刷新的触发与整体流程

4.1 两种触发方式

方式配置说明
定时自动触发cron: '0 8 * * *'每天 UTC 08:00 = 北京时间 16:00（含周末）。GitHub 的排队调度允许 15~60 分钟延迟，属正常现象
手动触发Actions 页面点 Run workflow调试、补跑时用，效果与定时完全一致

4.2 每次运行的 10 个步骤

1  Set up job            启动临时 Ubuntu 容器
2  Checkout              把仓库最新代码复制进容器          ← 全程只用仓库文件
3  Sync to latest main   强制同步到 main 最顶端（防版本错位）
4  Setup Node.js         安装 Node 20 环境
5  Install dependencies  npm ci 安装 axios/cheerio（约 20 秒）
6  Fetch & update prices 抓 OpenRouter → 过三道防线 → 改 data.js
7  Verify data.js        数据体检：字段完整 + 价格区间 + 波动检测
8  Show diff             打印本次改了哪几行
9  Commit & push         有变更 → 机器人提交回 main；无变更 → 跳过
10 运行摘要              全部步骤日志写入 Summary 页，出问题一眼可见

4.3 两种运行结果

结果现象后续
有价格变动Summary 显示「共更新 N 款」，生成新提交Cloudflare 自动部署，1~2 分钟后线上生效
价格无变化Summary 显示「价格无变化，跳过提交」不产生提交、不重新部署；页面上的「更新时间」保持原样是正常的——它只在价格真实变动时前进

4.4 保证「不写错数据」的三道防线

防线拦什么真实案例
单位闸门换算倍数错误的价格（超出合理区间 / 波动超 4 倍直接丢弃）曾把 Google 促销价 $1.2014/百万 误乘一百万倍变成 ¥852 万——被拦下后根治
严格匹配名字对不上的模型（碎片名、促销变体、批量折扣价一律不采信）碎片名 "2.0" 曾误配到「美团 LongCat 2.0」写入无关价格
提交前体检任何漏检的异常波动，直接阻止整个提交脏数据从未上过线；官方价锁定的模型（GPT-5.6 Sol、DeepSeek 两款）也在这一层保护

六、常见疑问解答

Q：自动更新时需要我的电脑开机吗？
A：不需要。一切发生在 GitHub 的服务器上，本地电脑只用于开发者改代码。
Q：机器人怎么有权限往仓库提交代码？
A：GitHub Actions 自带仓库写入身份（github-actions[bot]），只需在仓库设置里把 Workflow permissions 设为「Read and write」一次性授权。
Q：机器人抓错了价格怎么办？
A：三道防线让它几乎写不进错价；万一写入，仓库保留完整历史，可以一键回退到任意一天的版本。已被人工核实「报价不可信」的模型加入了永久排除名单。
Q：为什么有时打开网站，更新日期好几天没变？
A：说明这几天所有模型价格都没变（机器人每天照常核验，只是没有变化就不产生提交）。可在仓库 Actions 页面查看每天 16 点的运行记录确认。
Q：想增加新的数据源或新模型，改哪里？
A：数据源配置在 scripts/config.js，模型数据在 data.js。详细规则见同目录的《交接文档.md》。
